# 💰 Pay Service

외부 PG 장애 상황에서도 데이터 정합성이 깨지지 않는 간편결제 백엔드

금융 데이터의 **무결성(Integrity)**과 외부 의존성(PG사 등) 장애 시나리오에서의 안정성(Reliability)을 최우선으로 설계한 핀테크 백엔드 시스템입니다.

---

## 📝 프로젝트 소개

사용자가 가상의 지갑(Wallet)에 금액을 충전하고, 타인에게 송금하거나 결제할 수 있는 간편결제 서비스입니다. 단순한 기능 구현을 넘어, 분산 트랜잭션 환경에서 발생할 수 있는 데이터 불일치와 동시성 이슈를 시스템적으로 어떻게 방어하고 회복할 것인가에 집중했습니다.

---

## 💡 핵심 기술적 해결 과제

| 핵심 과제 | 해결 전략 | 상세 내용 |
| :--- | :--- | :--- |
| **외부 PG 장애 대응** | **트랜잭션 분리 및 서킷 브레이커** | 토스 API 타임아웃 대비 `READY` 상태 선 커밋으로 DB 커넥션 점유 최소화. Resilience4j를 이용한 재시도 및 자동 회복 로직 구현 |
| **데이터 무결성 보장** | **Spring Event + Outbox Pattern** | 회원가입 시 지갑 생성 실패를 방지하기 위해 ApplicationEvent로 비동기 처리. 실패 시 30초 주기의 보상 스케줄러가 회수하여 정합성 보장 |
| **동시성 제어** | **락(Lock) 전략 이원화** | 잔액 갱신 시 발생하는 경쟁 상태 방어. 낙관적/비관적 락을 비즈니스에 맞춰 혼용하고 Redis 기반 분산 락 병행 적용 |
| **의존성 격리** | **헥사고날 아키텍처** | Port/Adapter 패턴을 적용하여 외부 시스템 변경이 핵심 도메인 로직을 침범하지 않도록 설계 및 Fake 객체로 테스트 용이성 확보 |
| **관측 및 최적화** | **모니터링 및 부하 테스트** | Actuator, Prometheus, Grafana 스택으로 결제 승인 시간 실시간 추적. 부하 테스트를 통한 병목 지점(DB 커넥션 풀 등) 파악 및 개선 |

## 🛠️ 기술 스택

| 구분 | 기술 (Version) | 선택 이유 |
| :--- | :--- | :--- |
| **Language** | Java 17 | LTS 버전의 안정성 및 Record 등 최신 문법을 활용한 불변 객체 설계 |
| **Framework** | Spring Boot 3.x | 검증된 프레임워크 생태계 및 최신 의존성 관리 |
| **Database** | MySQL | ACID 트랜잭션 보장 및 락(Lock)을 활용한 데이터 정합성 관리 |
| **ORM** | Spring Data JPA | 도메인 중심 설계(DDD) 적용 및 Dirty Checking을 통한 상태 관리 |
| **Cache/Lock** | Redis + ShedLock | 분산 환경에서의 동시성 제어(분산 락) 및 다중 인스턴스의 스케줄러 중복 실행 방지 |
